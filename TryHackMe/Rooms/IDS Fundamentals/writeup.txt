What Is an IDS?

If attacker bypasses the network firewall via legitimate looking connection and performs malicious activity. To detect such malicious activity we need Intrusion Detection System(IDS).

Answer: Nay


Types of IDS

Categories of IDS based on deployment modes:
1. Host Intrusion Detection System (HIDS): 
Need to installed on individual host to get potential detection of security threats. 
Are challenging to manage in large networks as they are resource -intensive and require management on each host.

2. Network Intrusion Detection System (NIDS): 
Detecting potential malicious activities within the whole network, irrespective hosts. 
Centralized view of all the detections inside the whole network.

Detection Modes:
1. Signature-Based IDS: 
Each attack has its unique pattern, which is known as a signature. These signatures are preserved by the IDS in their databases so that if the same attack happens in the future, it gets detected by its signature and reported to the security administrators for action. 
Note: The signature-based IDS is unable to detect zero-day attacks. Zero-day attacks have no prior signatures (patterns) and are not saved inside the IDS databases.
Ex: Snort

2. Anomaly-Based IDS:
They detect abnormalities inside the network or system by comparing the current state with the normal behavior (baseline). However, this type of IDS may generate a lot of false positives (marking benign activities as malicious) because the nature of most legitimate programs matches the malicious ones.
Note: reduce the false positives generated by anomaly-based IDS by fine-tuning it (manually defining the normal behavior in the IDS).

3. Hybrid IDS: 
A hybrid IDS combines the detection methods of signature-based IDS and anomaly-based IDS to leverage the strengths of each approach. 

Note: Signature-based IDS can detect threats quickly, while other IDS can have a high processing overhead.

IDS Example: Snort 

1. Open source IDS solution developed in 1998.
2. Hybrid solution uses both signature and anomaly based detections to identify threats.
3. Rules file has several builtin attack patterns, users can disable and add custom rules to it.

Modes of Snort:
1. Packet sniffer mode: Used to perform analysis on the network traffic
This mode allows you to display the network traffic on the console or even output it in a file.
Use case: The network team observes some network performance issues. To diagnose the issue, they need detailed insights into the network traffic.

2. Packet logging mode: Used to perform the root cause analysis of attacks.
The network traffic needs to be logged for later analysis. The packet logging mode of Snort allows you to log the network traffic as a PCAP (standard packet capture format) file.
Use case: The security team needs to initiate a forensic investigation of a network attack. 

3. Network Intrusion Detection System mode: Snort’s NIDS mode is the primary mode
monitors network traffic in real-time and applies its rule files to identify any match to the known attack patterns stored as signatures. If there is a match, it generates an alert. 
Use case: The security team must proactively monitor their network or systems to detect potential threats.

Snort Usage

Note: During the installation of Snort, network interface and range needs to be provided as part of process. To use Snort to capture and detect intrusions in your whole network, you must turn on the promiscuous mode of your host’s network interface. 

All snort configurations file can be found in /etc/snort, rules folder has rules related to detection.

Rule format:
syntax: <action> <protocol> <sourceIP> <sourcePort> -> <DestinationIP> <DestinationPort> (<Rule-metadata(Message, SignatureID, Rule_version/revision)>)

Details on each component of rule format:
1. Action: Specifies which action to take when the rule triggers. ex: alert
2. Protocol: Refers to protocol that matches the rule. ex: "FTP", "ICMP"
3. sourceIP: Traffic originating from the provided IP. Usually we use any as part detection.
4. sourcePort: Traffic originating from the provided port. Usually "any" is used for detection.
5. DestinationIP: Traffic destination IP which is under monitoring. Ex: $HOME_NET -> variable defined as users whole network.
6. DestinationPort: Traffic reaching the destination port of provided DesinationIP. Usually "any" as part of detection.
7. Rule metadata: Defined metadata inside().
    a. Message: Displayed when subject rule is triggered. The message should indicate the type of activity detected. Ex: "msg:Ping Detected;".
    b. SignatureID: Unique identifier helps in differentiation. Ex: "sid:10001".
    c. Rule revision: Sets the rule revision number, modified on each rule modification with increment of 1. Helps in tracking rule version. Ex:"rev:1"

Rule Creation: Add rule to local rules and add ping detection rule.
Steps to follow for rule creation are(add to local.rules):
1. Open the "local.rules", using the command: "sudo nano /etc/snort/rules/local.rules"
2. Add ALERT: "alert icmp any any -> 127.0.0.1 any (msg:"Loopback Ping Detected"; sid:10003; rev:1;)"
3. Close and save the file.

Rule Testing: Using snort detection the ping action.
Steps to follow for rule testing:
1. Open Terminal and enter command:"sudo snort -q -l /var/log/snort -i lo -A console -c /etc/snort/snort.conf"
2. Use a new Terminal and enter command:"ping 127.0.0.1".
3. Check the earlier terminal where snort is executed and console should show the detection.

Running Snort on PCAP Files
Snort can be used for intrusion detection on real-time traffic. 
Scenario where you have historical network traffic logged in a file, and you have to perform a forensic investigation to determine any signs of intrusion through that traffic. This traffic is usually logged in the standard packet capture format "PCAP". Snort is also equipped to perform detections on these PCAP files containing historical network traffic.
command: snort -q -l /var/log/snort -r <PCAP file> -A console -c /etc/snort/snort.conf
